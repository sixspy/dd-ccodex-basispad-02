# 费率计提案 · basispad-02 —— 永续正确性口径取舍（当日锁册）

> 印记：**费率计提案** · 枪号 **basispad-02** · 类目「其它垂类行业 · web3 区块链 量化交易」
> 范围：资金费率草稿须正式计提才落台账。账号体系（`auth.py`、`models.USERS`）与库文件（`db.py` 建表/种子）勿动。

## 事故口径

ETH 费率快照仍是 `draft`，台账却已出现支付行，策略簿已实现盈亏被提前改写。
正确完成定义：

1. **仅 `draft` 快照可正式计提**；计提须在同一事务内写正式 `funding_ledgers` 行、
   改写 `positions.realized_pnl`、并把快照翻为 `accrued`，三步同成同败。
2. 仅 `accrued`（及其后被封批推进的 `settled`）快照下，正式台账允许有行。
3. 旁路不得提前落账：快照仍 `draft` 时任何正式台账行都属违规，由跨表对账点出。
4. 禁止只改费率页角标闪点：写口、盯市、时间线、审计、纸面簿联动，不做单点装饰。

## 甲乙口径（须择一，两边不得混用）

- **甲路径**：非 `draft` 或计提失败则**整笔拒写**，正式 ledger 零增。
- **乙路径**：意图计提只进影子 ledger 草案，正式台账零改，待原子升正。

### 本枪锁册：择 **甲路径**

锁册理由（当日定）：

- 现有写口 `POST /api/funding/snapshots/{id}/accrue` 的契约就是「正式计提」，
  甲路径与其语义一致，不引入影子状态机即可堵住「draft 已落正式行」的事故面；
- 题面三红的甲断言就是「draft 未过计提却仍写入正式 ledger」必须失败，
  甲路径以单事务原子写直接满足，正式区在提交前零改；
- 乙路径的影子草案、原子升正链路本仓不存在，混用会制造第二套真相，明确不采用。

落地约束：

- 计提事务用 `BEGIN IMMEDIATE` 打开，事务内以条件更新
  `UPDATE funding_snapshots SET status='accrued' WHERE id=? AND status='draft'`
  抢占；影响行数为 0 即整笔回滚并返回 409，正式 ledger 零增。
- 任何中途异常一律 `ROLLBACK`：快照仍 `draft`、正式 ledger 零行、`realized_pnl` 零改。
- 不新建影子表、不写影子正式行；争用败方只写争用记录（见
  `docs/funding_accrue_contention.md`，与本取舍段物理分开）。
- 禁止旁门双清：不靠作废/删行掩盖半成品，失败只回滚不补写。
